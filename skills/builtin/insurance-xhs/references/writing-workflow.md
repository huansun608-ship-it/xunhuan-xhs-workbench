# 从大方向到有作者判断的内容

写稿与改稿同时使用 [人感检查](human-speech.md) 和 [证据与实用性](evidence-and-value.md)：分别检查能否读懂、证据是否支撑及是否兑现标题。不将“顺口”视为成稿的充分条件。

## 1. 切口：从类别转向一个选择

“宝宝保险”是类别，不是最终选题。先确定读者这篇要完成的任务：弄懂一个疑问、比较几种选择、看懂条款或做一次检查。可切为：

- 已经住院：现在投保的商业医疗险，能不能承担本次费用？
- 看完多张配置表仍不会选：先分清自己担心医疗费用还是照护停工损失。
- 想用别人家预算照着买：哪些家庭条件不同，照抄就失去意义？

选择依据是用户目标与已有素材，不预设“越焦虑越好”。不在一个基础问答里同时塞入医保办理、四大险种、全部预算与健康告知。若任务本身是配置框架或分类比较，可以保留多个维度，用一致结构说明关系和取舍。

无实时搜索证据时，把这些称为候选切口，不称“热门搜索词”。

## 2. 开头：进入问题，而不是宣布主题

用户要求平台对标或课程口吻时，结合 [平台样本与口吻卡](platform-openings-and-voice.md) 选择有素材支持的过来人、实践者或明确立场。顾问自我介绍不固定插入正文第二句；先让作者的真实动作与取舍承担人设。五步用于检查理解推进，不机械凑五段。

弱：“宝宝保险怎么买？先弄清这三件事。”

更具体：“宝宝已经住院了，现在买一份医疗险，这次费用能报吗？”

后者是一般问题，不意味着作者真实收到过这条私信。没有真实记录时，不能加“今天一个宝妈问我”。如果引号是改写的概括问法，不标成逐字客户原话。

问题式开头也只是选项。用户原文有好的细节和声音时，优先保留，不把所有笔记改成同一种钩子。

## 3. 作者判断：说明先看什么、为什么

通用解释：“医疗险与重疾险的功能不同。”

可用判断：“如果你现在纠结的是住院账单，先看医疗费用保障；如果担心停工照顾孩子后家里收入减少，再考虑给付型保障能解决哪部分问题。两者不能只按价格比较。”

可验证的依据、适用条件与选择次序，比“专业、靠谱、有温度”更能表达服务价值。没有用户授权的专业身份时，使用一般科普口径，不代用户作核保、理赔或个性化销售决定。

## 4. 证据：按主张找材料

| 主张 | 所需证据 | 缺失时处理 |
|---|---|---|
| 我帮助过某客户 | 用户确认的真实记录及可公开范围 | 删个人经历；必要时另列教学示意 |
| 某产品承保或赔付条件 | 对应版本条款、健康告知及有关正式文件 | 不下产品结论；说明需核查的条件 |
| 某地新生儿医保期限或待遇 | 当地医保部门适用政策及时间 | 不套用全国统一天数，不承诺追溯报销 |
| 一年省几千或更划算 | 同条件、同保障范围的可核对测算 | 删除效果数字，讲比较方法 |
| 某办法提高咨询 | 有范围与口径的数据 | 称测试假设，不称已验证规律 |

条款不一定包含费率表、全部投保规则或最新核保政策，不能把一份条款PDF当成所有问题的答案。

## 5. 结尾：与问题、服务能力匹配

- **自查型**：让读者检查一个非敏感条件或查询官方要求，适合基础科普。
- **讨论型**：询问一般知识疑点，明确不要公开个人健康或身份资料。
- **服务型**：只有用户已确认可提供的服务和可用渠道时，说明什么问题可进一步协助、可协助到哪一步；敏感资料进入正式流程。

不用每篇都追求私信，也不把结尾写成万能“欢迎咨询”。转化应来自正文已体现的判断能力。

## 6. 交稿前检查

逐项判断，不用总分掩盖事实缺口：

- 题目是否承诺了明确的阅读任务？正文能否完成它？开头能否让目标读者识别自己？
- 有无超出依据强度的主张、虚构亲历或填充案例？
- 读者是否看得懂作者为什么这样建议？有哪些适用条件？
- 结尾动作能否兑现，是否诱导披露敏感信息？
- 遮住作者名字后，如果仍是通用稿，有真实素材可用时补入其判断过程；没有时承认是科普稿，不补造人设。
- 未解决的关键事实是否阻止该稿进入候选发布状态？

额外检查：多个知识点是否都服务本篇任务、关系是否说清？需要实证时是否提供了相应原文或测算？是否把“去看条款”当作最终答案？按 [人感检查](human-speech.md) 改掉术语堆叠，按 [证据与实用性](evidence-and-value.md) 补足真实依据和读后价值。

对用户默认直接交正文，最多用简短备注说明切口与必要限制，不附一大串内部分析。
