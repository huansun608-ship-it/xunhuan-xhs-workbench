# 内容事实与合规初查

本文件用于发现风险与准备审核材料，不出具法律意见或机构批准。规则应分清监管要求、机构内部规范与平台政策，不能混为统一的违禁词表。

先执行 [保险内容风控规则](content-risk-rules.md)。本技能不输出理财主题；惠民保按当地当年官方规定及对应条款介绍，不凭健康或年龄标签推荐投保。

## 1. 来源和适用性

对实质影响稿件的依据，记录：发布主体、正式文件名、文号或官方链接、发布日期/生效时间、适用地区和人员、核验日期。用户提供的资料也要核其来源。

- 法律监管：核对现行正式文本，注意征求意见稿与已生效文本的区别。
- 所属机构：核对个人账号、身份展示、素材制作、授权和对外发布审核流程。
- 平台：查询当前适用的金融内容、账号认证、导流与私信规则。普通私信不是天然获准的销售或资料收集渠道。

原包提到的《金融产品网络营销管理办法》、平台公约、KOS认证费用及路径，本版未核验其准确名称、现行状态或收费，不据此输出确定结论。监管机构名称和查询入口以当前官方渠道为准。

[negative-list.md](negative-list.md)保留原包的73条材料。原始“附件一”的发布主体、日期和适用对象尚未查明；其中法律依据、机构要求和示例须分别核对，不能用于最终定责。与已核实的现行规则冲突时，按现行适用规则处理。

## 2. 审核主张，不机械换词

| 内容 | 需要检查 | 改写原则 |
|---|---|---|
| 最好、第一、最划算等 | 是否有适用的事实、比较范围及规则限制 | 无依据就删主张，不换成另一句无依据的推荐 |
| 一定承保、一定赔 | 是否越过正式核保/理赔判断，是否忽略条件 | 解释必要核查条件，不作保证 |
| 理财主题、理财标签、投资收益导向表述 | 是否超出本技能的保障内容口径 | 删除相关选题或主张，转为保障需求、责任范围及预算评估 |
| 产品名、保费、费率、额度 | 来源、版本、测算条件、授权及审核要求 | 不凭空补，不因公开可查就认定可以自行宣传 |
| 停售、涨价、限额 | 来源是否真实、是否获准发布、是否制造销售紧迫感 | 不炒停、不编稀缺，不用中性替词保留逼单意图 |
| 同行/产品比较 | 数据是否同口径，是否片面、失实、贬损 | 讲事实、条件和差异，不一概贬低或禁止所有客观比较 |
| 新生儿医保与政策 | 地区、年份、参保条件及待遇规则 | 不全国套用天数，不保证追溯报销 |

## 3. 核保与理赔不是只翻一份条款

- 承保：核对适用健康告知、投保规则、年龄职业等限制；必要时走正式核保，以正式结论为准。
- 理赔：核对合同、实际出险事实、生效及等待期、责任和免责、所需材料，以正式处理为准。
- 产品数字：可能需要条款、费率表、投保条件等多份对应版本资料；不把条款PDF当万能来源。
- 一般科普可以解释判断路径，不能冒充个性化承保、理赔决定或保障结果保证。

## 4. 隐私与资料

不在公开评论区或普通平台私信索取病历、证件、完整保单及财务资料。只问完成当前一般说明必要的非敏感信息；需正式个案服务时说明机构认可的渠道和授权流程。

公开案例需有适当授权、必要去标识和范围控制。打码不自动消除重新识别风险，也不自动取得发布许可。不得为写稿把客户敏感原件上传到未经批准的AI工具。

## 5. 交付与发布状态

工作草稿可以另附：待确认事项 / 影响哪句结论 / 所需来源 / 谁或哪个正式流程能确认。用户补事实、机构确认授权；能自行查证的官方事实应尽量核实。

候选发布稿须解决影响结论的事实缺口，或删除相关主张；不能残留关键【待核】，不能把措辞修改视为机构审批。AI仅报告“完成哪些自查、还缺什么”。

遇到平台通知，先保存通知和原稿，按通知要求更正、撤下或申诉；不机械要求“只藏不删”“继续正常发”“等3-5天恢复”，不承诺删稿或认证对推荐权重的效果。
