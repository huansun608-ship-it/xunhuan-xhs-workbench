# 4 套切入角度

4 套不是同一篇的四个长度，而是**同一个事实底座上的四种读者入口**。先定角度卡，再写标题、封面和正文。

## 一、四个变量

每套角度由四件事决定，至少两项要和别的套不同：

1. **读者此刻在干什么**：在搜、在怀疑、刚遇到一件事、在算钱、在等一个政策。
2. **内容骨架**：反常识观点型 / 情绪故事型 / 攻略清单型 / 热点政策型 / 服务实录型 / 避坑揭秘型（定义见 insurance-xhs 的 writing-workflow）。
3. **证据类型**：条款与官方资料、真实经历、工作过程、假设算账、公开讨论。
4. **标题承诺**：点开后读者能得到的那个具体答案。

只换标题同义词、只换开头语气，都不算换角度。

## 二、角度库（6 选 4）

| 角度 | 读者处境 | 常用骨架 | 证据 | 封面骨架 |
|---|---|---|---|---|
| 搜索答案 | 正在搜“怎么选/要不要/多少钱” | 攻略清单型 | 条款、官方资料、比较维度 | 问题 + 3 个判断点 |
| 反常识判断 | 带着一个常见说法来求证 | 反常识观点型 | 条件、例外、条款原文 | 一句判断 + 条件分叉 |
| 场景代入 | 刚遇到一件事，想对号入座 | 情绪故事型或一般场景解释 | 真实经历（有才写）或公开场景 | 场景一句 + 三步动作 |
| 算账对比 | 在预算和方案之间取舍 | 避坑揭秘型或攻略清单型 | 假设、数字、责任边界 | 两列对比 / 账本 |
| 政策热点 | 听说新规，想知道影响 | 热点政策型 | 已核官方文件 | 文件一句 + 影响三条 |
| 服务实录 | 想知道“你到底怎么做” | 服务实录型 | 真实工作产物（脱敏） | 产物截图框 + 关键一步 |

## 三、默认组合

没有特殊材料时，按这四套起步：

1. **搜索答案**：把读者正在搜的问题一次答完。
2. **反常识判断**：指出一个常见说法在哪些条件下不成立。
3. **场景代入**：从一个具体处境进入，给出判断过程；没有真实经历就写“一般场景”，不冒充亲历。
4. **算账对比**：用一致维度比较，标清假设和条件。

有已核政策文件时，可用“政策热点”替换第 3 或第 4 套；有真实服务产物且可脱敏时，可用“服务实录”替换第 3 套。替换后仍要满足四套差异。

## 四、差异化硬检查

写完四套后，两两比较：

- 标题的第一个动作是否相同（都在问“要不要”、都在说“别急着”）？
- 开头第一句是否都在铺同一种背景？
- 骨架是否重复？出现 3 套同骨架 → 重做。
- 封面骨架是否重复？四张封面不能只换字。
- 把主题换成另一个险种，标题和开头是否几乎不变？若是，说明太泛。

任意两项相同，就要重做一套，而不是润色。

## 五、角度卡字段

写入方案 JSON 的 `angle`：

```json
{
  "name": "反常识判断",
  "reader_situation": "已经听过‘有医保就不用买’的说法，正在犹豫",
  "search_intent": "有医保还要不要买百万医疗",
  "skeleton": "反常识观点型",
  "evidence": "医保目录与商业医疗险责任边界的条款对照",
  "promise": "说清医保不覆盖的三类支出，以及哪些人仍要单独评估",
  "why_it_fits": "用户手里有条款对照材料，能支持条件式判断"
}
```

`promise` 必须能被正文兑现；写不出兑现方式，就换角度。

## 六、常见错误

- 4 套都是“3 个要点”清单，只是标题不同。
- 4 套都在开头说“很多人不知道”，读者看不出差别。
- 把“反常识”写成“大家都错了”，却没有条款或资料支持。
- 为了凑故事编客户、编对话、编理赔结果。
- 4 张封面用同一张底图，只换一行字。
- 一套写 300 字、一套写 1200 字，长短不是角度差异。
- 四套都承诺“看完就会选”，正文却只给“具体看合同”。

## 七、与标题、封面的关系

- 标题先按 insurance-xhs 的 title-writing 写，再从角度卡检查：这个标题是不是这套角度唯一的入口？
- 封面文案不是标题的复制。封面负责“一眼看懂在讲什么”，标题负责“为什么现在点开”。
- 封面、标题、正文必须兑现同一个承诺；任何一处换了承诺，四套就会互相打架。
