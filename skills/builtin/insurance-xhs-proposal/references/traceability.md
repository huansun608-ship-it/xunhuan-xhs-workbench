# 分项溯源与事实状态

两个问题必须分开：

- **表达溯源**：标题、封面、正文的写法参考了哪篇案例，借鉴了什么，不搬什么。
- **事实依据**：稿子里的保险结论对不对，依据是哪份文件、哪一条、哪个版本。

把两者混在一起，就会出现“参考了一篇高赞笔记，所以这个结论是对的”的假证明。

## 一、表达溯源：来源优先级

按顺序取，能用前面的就不用后面的：

1. **本地研究包**：`skills/builtin/insurance-xhs/assets/research/critical-illness-20261122/notes.json`。34 篇重疾险图文，含 id、标题、作者、来源链接、发布日期、正文、互动数、本地配图、核对状态。只适用于重疾险相关主题。
2. **本次实时检索**：登录态可用时，用 `skills/shared/scripts/redbook_read.py search "关键词"` 只读搜索；一次一篇、按 human-paced，不连续猛拉。把结果存到 `outputs/<主题>/assets/references/`，不要把整段正文抄进方案。
3. **用户提供的链接或截图**：记录用户给的链接、截图文件名、可见范围；截图没有公开链接时，写进 `refs_note`，不要伪造成 URL。
4. **方法文档**：insurance-xhs 的 title-sources、community-title-workflow、writing-workflow 等。只能标 `kind: 方法`，不能冒充案例。
5. **都没有**：`refs: []` + `refs_note: "无对标样本（原创）"`。诚实留空，比编一个链接强。

## 二、怎么选案例

- 同角色：消费者求助、消费者吐槽、经纪人答疑、经纪人服务实录，不要混。
- 同任务：求助 / 吐槽 / 报喜 / 找同伴 / 分享发现 / 搬来讨论。
- 同主题：至少同一个保障问题；只同险种不算。
- 先看标题与封面，再看正文；不按点赞高低选。
- 一篇案例最多借 1–2 个动作；借太多会变成洗稿。

## 三、引用格式

每个 `refs[]` 元素：

```json
{
  "kind": "案例",
  "title": "原帖标题",
  "author": "作者名",
  "date": "2026-05-28",
  "url": "https://www.xiaohongshu.com/explore/…",
  "borrowed": "借了‘先给结论再解释条件’的开头顺序，以及把读者原话放进第一句",
  "not_borrowed": "不搬作者的新手身份、具体产品结论和评论区个案",
  "checked": "已看正文与封面"
}
```

规则：

- `url` 必须真实可打开；不能写“小红书搜索”“见截图”代替。
- `borrowed` 具体到动作、结构或句式，不能写“学习了写法”“借鉴了思路”。
- `not_borrowed` 写清不搬的身份、经历、数字、产品结论；这是防止洗稿和冒用的关键。
- `checked` 如实：只看标题写“仅看标题”，只看封面写“仅看封面”，没打开就不要引用。
- 每个位置 1–3 条即可；超过 3 条说明还没抓住重点。

## 四、事实清单

每个 `facts[]` 元素：

```json
{
  "statement": "百万医疗险的续保需要看合同约定，不能只看宣传页",
  "status": "已核",
  "basis": "《XX医疗保险条款》（2026 版）第 X 条‘续保’，2026-11-20 版，适用于中国大陆",
  "next_step": "",
  "impact": "若条款并非如此，正文第二段的判断要整段重写"
}
```

三种状态：

| 状态 | 什么时候用 | 必须写 |
|---|---|---|
| 已核 | 能指到具体文件、条款、页码、版本、地区 | `basis` 四要素：文件 + 位置 + 版本/日期 + 地区 |
| 待核实 | 只有口头转述、宣传页、截图不全、条款未拿到 | `next_step`：查哪份文件、看哪一条、向谁确认；`impact`：若为假改哪句 |
| 不适用 | 纯方法、观点、经验，不涉及产品事实 | 可留空 |

口头转述不算“已核”。用户说“我们这个产品能续保”也要标待核实，除非给出条款或官方资料。

## 五、哪些话必须进事实清单

- 产品名、公司名、险种全称。
- 保险责任、免责、等待期、免赔额、赔付比例、医院范围、续保条件。
- 保额、保费、缴费期、现金价值、收益演示。
- 健康告知、核保结论、既往症、职业限制。
- 监管文件、政策口径、统计数据、理赔时效。
- 任何具体数字（包括“便宜 30%”“能赔 60 万”）。

一般常识（“保障范围以条款为准”）可以不单列，但不能用它代替具体解释。

## 六、在方案里怎么展示

- 标题、封面、正文各自带一组 `refs`，分别显示在对应内容下方，不集中堆到文末。
- 事实清单放在正文旁边；正文里标了“（待核实）”的句子，必须在表里有对应行。
- 对比页由 `build_plan.py render` 生成，溯源和事实表会自动排进去，不要手改 HTML。
- 导出 Markdown 时同样保留分项溯源和事实表。

## 七、禁止

- 编造链接、作者、日期、点赞数、评论内容。
- 把高互动当专业结论正确，把“原帖说”当“事实是”。
- 把研究样本的产品结论、身份、经历写成作者自己的。
- 用“业内都知道”“大家都这样”“公司培训说”代替依据。
- 把“待核实”藏在文末小字，正文却写成确定结论。
- 用一张截图证明多个不同事实。
